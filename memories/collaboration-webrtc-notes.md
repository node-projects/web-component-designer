# Collaboration and WebRTC

- `mergeCollaborationHtml(base, incoming, accepted)` merges independent attributes/styles and uses the incoming edit for overlaps; the transport/coordinator supplies ordering, not browser clocks. It also supports the uncommon source/canvas combination.
- `applyCollaborationHtml(document, html, attributesChanged?)` reconciles retained items by saved ID with positional fallback. Keep live DesignItem/selection identity across remote property edits. Consumers can refresh declared custom-element properties through the attribute callback. Do not replace a whole canvas for ordinary remote property updates.
- Remote CSS changes must update both the style model and live DOM, including removal, custom properties and priorities, without entering local undo history. The model-only `_withoutUndoSetStyle`/`_withoutUndoRemoveStyle` helpers do not render changes; apply CSS actions directly. Browser regressions must compare rendered styles as well as serialized HTML.
- Use `collaborationHtmlSignature` for state equality; attribute and independent CSS declaration ordering must not count as a new remote edit. Child order, text, property values and priorities remain significant.
- Collaboration selection/comment overlays have one root owner and allocate item overlays only for actual remote targets. Cursor refreshes target permanent root overlays, never all designer extensions. Node indexes are cached per document and invalidated by structural content events (`added`, `removed`, `moved`, `parsed`); property-only changes do not alter indexes.
- Single-element attribute/style updates with identical surrounding markup parse only that element, locating it by the opening tag's preorder position in that exact HTML revision. Saved IDs are unnecessary; SVG snippets retain their namespace. Comments, raw-text elements and structural/source edits use full reconciliation. Observe document content events while snippet parsing yields so concurrent local changes fall back to the full three-way merge.
- HTML writers track the final character directly; indexing the accumulated output after every append can repeatedly flatten large string ropes. Cache CSS shorthand results by each item's ordered declarations, preserving output, declaration ordering and important priorities. Keep cache refresh coverage for style edits and undo.
- Run `node --test packages/web-component-designer/tests/CollaborationOverlays.browser.mjs` for large-canvas cursor/selection/comment behavior, targeted property parsing, concurrent changes and cleanup. Jest covers node-index invalidation, text writing and HTML whitespace/raw-text compatibility.
- Comment menus/prompts use the basic designer's shared `translationService`, not a collaboration-specific callback. Preserve user comment bodies; standalone containers provide English fallback through `DefaultTranslationService`.

- Manual signaling carries `requestInitialSnapshot` in `hello` and `hello-ack`. Snapshot ownership must follow the peers' document state, not the copied signaling direction.
- `WebRtcTabCollaborationTransport` accepts an optional `rtcConfiguration` and passes it to `RTCPeerConnection`; cross-machine connections generally require appropriate STUN/TURN configuration.
- Do not add public TURN endpoints or browser-exposed long-lived provider credentials as defaults. Keep provider-specific credential generation outside the transport.
