# SVG geometry editing

- Marker hover outlines are reconstructed in the source geometry's user space. The temporary marker group under the owner SVG must apply `ownerSvg.getScreenCTM().inverse() * source.getScreenCTM()` so ancestor and element transforms affect the outline exactly as they affect the rendered marker.

- SVG geometry preview translation is already local with respect to individual CSS `rotate`/`scale`, so the placement commit skips that remapping for supported SVG geometry. It then maps the remaining offset through the inverse linear part of the authored `transform`; translation components are ignored because this is an offset vector.
- `SvgRectGeometryReader` reads rendered geometry from `getBBox()` and carries serialization hints for style-versus-attribute storage and units. Writes must honor those hints instead of always creating attributes.
- `UnifiedGeometryExtension` creates drag state on pointer-down for capture, but commits only after a non-zero move sets `geometryChanged`; clicking a handle alone must not create an undo entry.

- `ServiceContainer.options.svgEditingMode` selects `'object'` (default) or `'content'`. Object mode selects the outer SVG for resizing; content mode edits painted geometry directly without selecting the viewport. Normal object-mode clicks select the outer object for resizing. Double-click a geometry or choose Edit points to enter node editing; Done or Escape returns to the object. Code/source handle selection also activates the geometry editor. Do not display node handles for ordinary object selection.
- The contextual SVG toolbar owns paint and node actions. Node selection, coordinates, segment conversions, insertion, deletion and subpath closure use the document undo system. Cubic/quadratic insertion splits controls without changing the curve; unsupported arc/smooth-segment insertion is disabled.
- During node dragging, snapshot the exact geometry attribute/style values before preview writes. Restore them before committing through DesignItem, or on cancellation; serializing a geometry snapshot loses authored precision/formatting and breaks undo.
- Shape-library assets load locally on first use. The palette searches categories from `assets/shapes/library.json`; source revisions and MIT attribution live alongside it. Shapes are ordinary SVG paths with a viewBox, rather than an embedded external editor or remote runtime dependency.
- Interaction checks: `node --test packages/web-component-designer/tests/SvgEditing.browser.mjs`. These use native mouse/keyboard input and cover drawing, object/node modes, snapping, undo, curve splitting, compound paths, paint, resizing and local palette loading.

- SVG controls dock above the viewport, in a separate stacking context from drawing overlays. `svgEditingToolbar` controls visibility; `canvas.setSvgEditingToolbarVisible()` updates an attached view. Hiding controls does not disable handles or keyboard editing. Dock resizing preserves the screen anchor and navigation uses the actual remaining viewport.
- Node click selection updates appearance immediately, including handles without source-map entries. Selection styles must beat the base `.svg-path` style. Modifier keydown and keyup recompute previews from the original drag snapshot at the latest cursor position; Ctrl+Alt moves the shape, Shift locks an axis, and Alt bypasses snapping.
- Stroke icons share `SvgStrokeStyleControl`; fill/stroke use the existing `ColorInput` with opt-in `allow-none`, which exposes No paint inside its popup. Drawing popups retain wheel gestures and disable scroll chaining so palette scrolling cannot navigate the canvas.
